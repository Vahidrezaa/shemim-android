# ۰۵ — تغییرات حداقلی بک‌اند (فقط همین‌ها)

> **تعهد:** کل تغییرات سرور این پروژه در همین سند است. هیچ فایل دیگری از وب تغییر نمی‌کند و رفتار فعلی مرورگر/PWA یک بایت هم عوض نمی‌شود. همهٔ موارد در فاز ۵ پیاده‌سازی می‌شوند، فایل‌های آمادهٔ کپی در پوشهٔ `server/` ریپو قرار می‌گیرند و **قبل از تحویل، روی محیط تست/عضو تست بررسی می‌شوند.**

## چرا اصلاً تغییر لازم است؟

1. **پوش:** وب از Web Push با VAPID (مرورگر) استفاده می‌کند؛ اپ نیتیو فقط با FCM پیام می‌گیرد. تکرار الگوی VAPID در اپ اندروید عملاً ممکن نیست (نیازمند Service Worker مرورگری است).
2. **به‌روزرسانی اپ:** اپ خارج از مارکت توزیع می‌شود؛ باید از سرور بفهمد نسخهٔ جدیدی هست یا نه.

## ۱. فایل جدید: `api/fcm.php` (کامل، بدون دستکاری فایل‌های دیگر)

**جدول جدید** (خودساز در اولین اجرا، مثل بقیهٔ جدول‌های پروژه):

```sql
CREATE TABLE IF NOT EXISTS `fcm_tokens` (
  `token` VARCHAR(255) PRIMARY KEY,
  `member_id` VARCHAR(50) NOT NULL,
  `created_at` VARCHAR(20),
  `last_seen` VARCHAR(20),
  `app_version` VARCHAR(20),
  INDEX `member_id` (`member_id`)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**اکشن‌های جدید (سه تا):**

| اکشن | دسترسی | ورودی | شرح |
|---|---|---|---|
| `fcmRegister` | عضو لاگین‌شده | `token`, `appVersion` | ثبت/تازه‌سازی توکن این گوشی برای عضو جاری |
| `fcmUnregister` | عضو لاگین‌شده | `token` | حذف توکن (خروج/تعویض حساب) |
| `fcmTest` | فقط مدیر | — | ارسال یک پیام آزمایشی به توکن‌های خود مدیر |

**توابع داخلی (با امضای قرینهٔ Web Push موجود):**

- `fcm_sendToAll($pdo)` و `fcm_sendToMember($pdo, $memberId)` — دقیقاً همان نقاط ارسال `push_sendToAll/push_sendToMember` فعلی، با همان منطق «کدام اطلاعیه برای چه کسی» (تولد عمومی / هشدار معوقهٔ شخصی / یادداشت‌های `plnote_` / رویدادهای قرعه‌کشی). انتخاب پیام‌ها با یک تابع مشترک که از همان کوئری‌های push.php استفاده می‌کند، تا مسیر وب و اپ **همیشه یک پیام** را ببینند.

**ارسال به FCM — روش استاندارد فعلی (HTTP v1):**

- سرویس‌اکانت Firebase (فایل JSON) در فایل اسرار (الگوی موجود `shemim-secrets.php`) نگهداری می‌شود.
- ساخت JWT_RS256 با `openssl_sign` (بدون نیاز به کتابخانهٔ خارجی — cPanel محدودیت کامپوزر دارد)، تبادل با توکن OAuth2، کش توکن در `app_settings` تا ساعت انقضا.
- ارسال با **data payload** (نه notification payload) تا اپ خودش کانال/آیکون/Deep Link را بسازد:
  `{"type":"notify"|"warning"|"draw"|"reminder", "title":…, "body":…, "id":…, "target":…}`
- رفتار خطا: توکن نامعتبر (404/410) → حذف از جدول؛ خطای موقت → لاگ در `api_error.log`؛ **هرگز** روی پاسخ اکشن اصلی اثر نمی‌گذارد (همان فلسفهٔ try/catch کدهای فعلی).

## ۲. قلاب در `api/push.php` (تنها فایل تغییریافتهٔ موجود — ۶ خط)

در انتهای دو تابع موجود `push_sendToAll` و `push_sendToMember`، فراخوانی قرینه اضافه می‌شود:

```php
if (function_exists('fcm_sendToAll')) {
    try { fcm_sendToAll($pdo); } catch (Throwable $e) { error_log("FCM all: ".$e->getMessage()); }
}
```
(و مشابه آن برای member). با این کار هر ۸ نقطهٔ ارسال فعلی (تولد، تشکر معوقه، یادآوری گردشی، هشدار سررسید، نظرسنجی، رویدادهای قرعه‌کشی) **خودکار و بدون دستکاری** به اپ هم می‌رسند، چون همگی از همین دو تابع می‌گذرند.

## ۳. اکشن جدید `appConfig` (در `api/core.php` — یک case جدید)

```json
{
  "success": true,
  "minAppVersion": 14,          // زیر آن: بلاک به‌روزرسانی اجباری
  "latestAppVersion": "1.0.0",
  "apkUrl": "https://…",        // اختیاری: لینک GitHub Release شما
  "fundName": "…", "registrationEnabled": true, "trialExpired": false
}
```
عمومی (بدون لاگین) تا صفحهٔ به‌روزرسانی اجباری قبل از لاگین هم کار کند.

## ۴. `api.php` — یک خط require

```php
require __DIR__ . '/api/fcm.php';
```

## ۶. آنچه از شما برای این بخش لازم است

1. **پروژهٔ Firebase:** ساخت رایگان در console.firebase.google.com → افزودن اپ اندروید با package `com.shemim.app` (نهایی‌شده — ADR-011) → فعال‌سازی Cloud Messaging → دانلود **google-services.json** (برای بیلد اپ) و **سرویس‌اکانت JSON** (برای سرور).
2. آپلود ۵ فایل بالا طبق راهنمای فاز ۵ (همان روش Upload واقعی که در README وب توصیه شده).

## ۷. نکات صداقت دربارهٔ محدودیت‌ها

- FCM در ایران بدون فیلترشکن **روی برخی اپراتورها/دستگاه‌ها** ممکن است دچار تأخیر شود (تحریم سرویس‌های گوگل روی برخی رام‌های چینی). راهکارهای کاهشی داخل اپ: fallback به WorkManager polling سبک (`pushLatest` موجود) وقتی FCM دیر می‌رسد + امکان «همگام‌سازی هنگام باز شدن اپ» که مستقل از FCM است. اگر پوش سریع برایتان حیاتی بود، جایگزین‌های ایرانی (پوشه/ناتیفای‌پلیتر) هم قابل افزودن‌اند — تصمیم با شما (سؤال باز Q3 در سند ۰۷).
- سهمیهٔ پیام FCM برای این مقیاس (ده‌ها کاربر) کاملاً رایگان و بی‌دردسر است.
